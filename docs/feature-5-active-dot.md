# 功能 5：活跃标记配色

侧边栏（以及工具行、jobs、subagent 面板）上表示「这个会话正在跑」的活跃标记，提高它的对比度。**一行 JS 都不跑**，实现是[那张样式表](../src/client/index.js)里的三条规则。

上游的 `StateDot` 用一个 8 格 SVG 做追逐动画。它不明显的根因是**不透明度，不是色相**：8 格的基线是 `opacity: .15`，动画任一时刻只有 1 格到 `1.0`，其余常年停在基线——按 `deepseek-450` 对深色底算只有 1.21:1，换成纯白也才 1.61:1。所以主要手段是把基线抬到 `.6`，换色是次要的。

```css
svg[data-state='ongoing']                       { --dsh-state-ongoing: rgb(21, 94, 117); }
body[data-ds-dark-theme] svg[data-state='ongoing'] { --dsh-state-ongoing: rgb(34, 211, 238); }
svg[data-state='ongoing'] rect                  { animation-name: dsh-oi-state-dot-chase; }
```

四条不能随手改的：

1. **选择器只能挂 `data-state`**。`._cell_10orb_54` 与 `._matrix_10orb_4` 都是 CSS Module 构建期哈希出来的，逐版本变；`data-state` 是 TSX 里的字面量。
2. **动画换自己的名字，不去覆盖同名 keyframes**。上游那个 keyframes 在发布产物里同样被哈希成 `_dsh-state-dot-chase_10orb_1`，写一份同名的覆盖不到它。
3. **靠特异性赢，不靠插入顺序**。`svg[data-state] rect` 是 (0,1,1)，压过上游那条 (0,1,0)，两张样式表在 `head` 里谁先谁后都不影响结果。
4. **深浅两个值不能合成一个**。单色做不到两边都亮——亮青在白底上即便 `opacity: 1` 也只有 1.81:1。

换青色是为了避开三个已被占用的语义色：品牌蓝同时是选中态、链接与 focus ring，`green-500` 是 done，`amber-500` 是 warning。覆盖**不限定侧边栏**：同一个 `data-state="ongoing"` 在别处有同样的 1.2:1 问题，同一语义给同一个颜色。

## 实测读数

20 条断言全过时的读数（深色主题）：

| | 覆盖前 | 覆盖后 |
| --- | --- | --- |
| 暗格像素 / 对比度 | `rgb(30,37,57)` / **1.20** | `rgb(28,135,152)` / **4.31** |
| 亮格像素 / 对比度 | `rgb(86,134,254)` / 5.42 | `rgb(34,211,238)` / **10.09** |
| 四相位 opacity | `[1, 0.6, 0.35, 0.15]` | `[1, 0.85, 0.7, 0.6]` |

浅色主题下暗格 `rgb(115,158,172)` / 2.91、亮格 `rgb(21,94,117)` / 7.27。暗格提升 3.59×，亮暗之间仍有 2.34× 的差，动画的节奏没有被抹平。

## 已知限制

- 覆盖认的是 `svg[data-state='ongoing'] rect` 这个结构。上游把 `data-state` 挪到别的元素上、或把 8 格从 `rect` 换成别的标签，覆盖整条失效且不报错——表现是标记退回原来那个 1.2:1 的样子。`verify:dot` 的第一条断言（反查 `._cell_` / `._matrix_`）会先撞上这种改动。
- 对比度是对着**标准主题底色**保证的。装了壁纸主题一类的第三方外观插件时，标记压着的是一张照片，实际对比度逐像素变化，插件管不到。
- 深浅两个色值写死在 CSS 里，不跟随上游的调色板 token。上游改了主题底色，这两个值不会自己跟上；表现是对比度偏离设计值，仍然不报错，要靠重跑 `verify:dot` 才看得出。
